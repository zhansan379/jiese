# 戒色知识库 RAG 问答系统 —— 实现文档

> 技术栈：FastAPI + React 18 (Vite + Ant Design 5 + Framer Motion) + PostgreSQL（本地 Docker，psycopg2 连接池） + jieba BM25（可选向量检索与 LLM 生成）
> 语料：《戒为良药》（飞翔，约 216 万字，140 章主题式文集）+《戒者录》（前辈 编，约 125 万字，108 位作者合辑）

---

## 1. 系统目标

1. **在线阅读**：两本书的完整在线预览（目录导航、章节翻页、锚点定位）
2. **知识库问答**：针对两本书内容的 RAG 问答，答案附引用
3. **引用跳转**：答案中的每条引用展示所用原文，点击"查看原文"跳转到阅读器中该段落的位置并高亮

## 2. 语料特点（决定设计的实测数据）

| 维度 | 戒为良药 | 戒者录 |
|---|---|---|
| 字数 | 216 万 | 125 万 |
| 结构 | 单作者 140 章，一章一文件，章内无小标题 | 108 位署名作者，180 文件，309 目录节点（大量 `#toc_id` 文件内锚点） |
| 章内形态 | 案例三元组（【戒友提问】→答：→分析：）、【XX分类】知识块、口诀 | 第一人称心路叙事（阶段伪标题是加粗短段落而非 h 标签）、佛学开示笔记 |
| 重复 | 书内列表复述；被戒者录整篇转载（"戒色八年记" 244/249 段与戒为良药完全重复） | 约 5.3% 段落与戒为良药完全重复，跨书完全重复段 386 对 |
| 术语 | SY/手淫/撸管、遗精/梦遗/滑精/频遗、意淫/YY、心魔、断念、神衰、社恐 等黑话+中医词汇密集 | 同一术语体系；佛学色彩更浓 |

由此确定的设计取向：

- **数据结构**：树形文档模型（书 → 文档页 → 目录锚点小节 → 段落）拍平为带层级元数据的 chunk（父子信息以 breadcrumb + 段落 ID 列表承载）
- **检索**：BM25（jieba + 自定义词典 + 同义词扩展）为主，可选 API 向量检索 + RRF 融合；规模约 7k chunk，全内存毫秒级，不需要向量数据库
- **去重**：文本级重复（精确 + 近似）只打标记不物理删除，重复 chunk 不进检索索引，阅读器仍显示原文
- **不做**知识图谱/图数据库、自主迭代检索循环（章节自包含，无多跳需求）——关系抽取等留作扩展
- **多轮**：对话历史查询改写（配置 LLM 时启用）+ 同义词扩展；不做 agent 循环

## 3. 总体架构

```
┌────────────────────────── React (Vite) ──────────────────────────┐
│  问答视图                书架/阅读视图（共享阅读器组件）           │
│  ├ 消息流                ├ 目录侧栏（NCX 层级）                  │
│  ├ 引用卡片(原文+出处)    ├ 段落渲染（para_id 锚点、高亮、滚动）   │
│  └ "查看原文" ───────────┘ 跳转定位 + 黄色高亮 chunk 段落          │
└──────────────────────────┬───────────────────────────────────────┘
                     REST /api
┌──────────────────────────┴───────────────────────────────────────┐
│ FastAPI                                                            │
│  /api/books /api/books/{id}/toc /api/docs/{id}        ← 阅读服务  │
│  /api/chat /api/search /api/health                    ← 问答服务  │
│  ├ 查询预处理：同义词扩展（术语表）                                 │
│  ├ 混合检索：BM25 (内存) ⊕ 可选向量 (npy) → RRF 融合               │
│  ├ 生成：LLM(可选, OpenAI 兼容) / 无 LLM 时返回原文摘录模式         │

```

## 4. 数据模型（PostgreSQL，本地 Docker）

```sql
books   (id, title, author, doc_count, char_count)
docs    (id, book_id, seq, file, title, char_count, para_count)   -- 一个 EPUB 内容文件 = 一页
paras   (id, doc_id, seq, kind, text, elem_id)                    -- kind: heading|para；elem_id 供锚点
toc     (id, book_id, doc_id, para_id, title, level, seq)         -- NCX 目录节点，锚定到段落
chunks  (id, book_id, doc_id, para_ids JSON, seq,
         breadcrumb, chapter_title, section_title, author, doc_type,
         text, tokens JSON, dup_of, embedding vector(1024))
         -- dup_of 指向规范版本；embedding 为 pgvector 列（bge-m3，HNSW 余弦索引）
```

- 连接：`app/db.py` 提供 `ThreadedConnectionPool`（DictCursor，FastAPI 线程池安全）；DSN 由 `PG_*` 环境变量配置，默认 `postgres/postgres@127.0.0.1:5432/jiese`（构建脚本幂等，每次 DROP 重建）
- 向量存储：**pgvector 为唯一生产来源**（`chunks.embedding` + HNSW `vector_cosine_ops` 索引），启动时整列载入内存矩阵（查询期零 SQL、毫秒级点积）；`scripts/embed_index.py <model>` 嵌入后同时写 PG（生产模型）与 `data/vectors/*.npy`（评测库）
- **按书过滤**：`/api/chat`、`/api/search` 支持 `book_id`（jwly/jzl/缺省全部）；向量侧用 book mask，BM25 侧取 3 倍候选后过滤；前端聊天头部有范围选择器
- `para_id` 全局唯一（阅读器锚点、引用高亮的单位）
- `chunk.para_ids` 记录构成该 chunk 的段落 ID 列表 —— 引用跳转的依据
- chunk 不进检索索引当且仅当 `dup_of IS NOT NULL`

### 分块规则（构建期）

1. 目录锚点标题（h1/h2/h3 带 elem_id）强制分块边界，并更新 chunk 的 chapter/section 上下文
2. 段落级窗口：目标 ~420 字、硬上限 900 字，边界优先落在"分析："段之后、`案例N：`/`【XX】`短标记段之前；chunk 间携带一段重叠（50–200 字）
3. 案例三元组（【提问】+答：+分析：）尽量不跨 chunk 拆散
4. doc_type 启发式：标题含"案例"→案例分析；署名作者存在→个人叙事；含开示/印光/元音/禅→佛学开示；含口诀/德训→口诀德训；否则→方法论

### 去重规则（构建期）

1. 规范化（去空白与标点）后 MD5 精确去重
2. 近重复：8-gram shingle 候选（倒排索引过滤高频 shingle）→ Jaccard ≥ 0.85 聚簇
3. 规范版本选取：戒为良药优先于戒者录（原创优先）→ 同书内靠前章节优先
4. 重复 chunk 仅标记 `dup_of`，不删除；阅读器不受影响

### 术语表（内置，检索期查询扩展）

同义词族（查询命中任一成员 → 扩展整族入 BM25 查询与向量查询文本）：

```
SY / 手淫 / 撸管 / 撸 / 自渎 / 恶习
遗精 / 梦遗 / 滑精 / 频遗 / 失精
意淫 / YY / 邪念 / 邪淫念
神衰 / 神经衰弱 / 神经症
社恐 / 社交恐惧 / 社交恐惧症
痤疮 / 青春痘 / 痘痘
脑力 / 记忆力 / 注意力
早泄 / 阳痿 / 性功能
断念 / 断念口诀 / 念起即觉
```

jieba 自定义词典同时收录领域词（固肾功、欲望休眠期、戒断反应、无害论、不净观、白骨观、心魔、伤精、撸管……），避免分词切碎导致 BM25 失配。

索引噪声过滤（`tokenize()` 与查询侧共用同一规则）：剔除纯标点/符号（曾占 token 总量 23.7%）、1–2 位纯数字、单英文字母、扩充停用词；**保留 3 位以上数字**（章号/天数/年份在该领域有真实检索价值，如"第137章"可精确命中）。

## 5. 检索与生成

### 向量模型选型（18 题章节级评测集，2026-10 实测）

| 方案 | hit@3 | hit@6 | MRR |
|---|---|---|---|
| **bge-m3 + BM25 混合（采用）** | **88.9%** | **100%** | **0.858** |
| Qwen3-Embedding-8B 向量 | 77.8% | 88.9% | 0.775 |
| Qwen3-Embedding-0.6B 混合 | 83.3% | 83.3% | 0.741 |
| BM25 基线 | 66.7% | 94.4% | 0.673 |

采用 SiliconFlow 的 `BAAI/bge-m3`（1024 维，免费档，全量 6434 块嵌入约 2 分钟）；
`bge-large-zh-v1.5` 因 512 token 输入上限不适合 600 字 chunk 被淘汰。评测脚本：
`scripts/embed_index.py`（仅嵌入）+ `scripts/eval_retrieval.py`（评测集对比），换模型可复评。

### 重排序（已启用：SiliconFlow `BAAI/bge-reranker-v2-m3`，与 RRF 排名加权融合 w=0.5）

22 题评测（含 4 道口语化难题）实测：

| 方案 | hit@3 | hit@6 | MRR |
|---|---|---|---|
| **RRF + bge-reranker 融合 w=0.5（采用）** | **86.4%** | **90.9%** | **0.841** |
| RRF + Qwen3-Reranker-4B 替换排序 | 81.8% | 86.4% | 0.670 |
| 无重排基线 | 81.8% | 90.9% | 0.748 |

关键结论：reranker **替换**排序反而劣化（丢标题信号、偏好叙事文本）；把 rerank 排名以 RRF 方式**融合**进现有排序（`score += 0.5/(60+rerank_rank)`）才全面超越基线。文档输入为"章节标题+正文"。失败自动回退 RRF 序；延迟 +0.6s。

**按分数过滤**：最终引用以 rerank 绝对分数 ≥ 0.1 兜底（评测：相关集零损失、离题集 6→0.9 条）；过滤后为空时不调 LLM，直接返回“未找到相关内容”。纯数量的 RRF 相对分数兜底被评测否决（分数分布过扁平，任何比例都切不动）。

### 检索流水线（每次提问）

```
query
 ├─ (有历史且配置了LLM) 1 次廉价改写：对话历史+当前问题 → 独立查询
 ├─ jieba 分词 + 术语族扩展
 ├─ BM25 (k1=1.5, b=0.75, 内存索引, 启动时由 chunks.tokens 重建)
 ├─ [可选] 向量：embedding API → 与构建期 npy 矩阵余弦
 ├─ RRF 融合 (k=60) → top24
 ├─ 候选为空 → 一次无扩展降级重试（有界兜底，规则触发非 LLM 触发）
 └─ top_k (默认5) → 引用列表
```

### 生成

### 生成（已启用：SiliconFlow `Qwen/Qwen3-32B`，实测普通问答约 10-15s、深度思考约 25s）

- **LLM 模式**（`OPENAI_BASE_URL` / `OPENAI_API_KEY` / `LLM_MODEL`，OpenAI 兼容协议）：
  - System prompt：戒色知识助手；仅依据给定摘录回答；引用标注 [n]；共识与分歧分开陈述；忠实转述、注明出处；不渲染为医学诊断
  - Context：编号摘录（breadcrumb + 原文）；答案解析 [n] 关联引用
  - **深度思考**：追加系统级分点分析指令（结论→机理→方法→误区→案例→行动建议），max_tokens 提升至 2000，实测产出约 1800 字结构化长答案
  - **智能搜索**：检索端双倍候选 + 每章最多 3 条多样性约束 + 引用数 6→8，与 LLM 生成天然兼容
  - **多轮改写**：带历史时先做一次廉价改写（实测"那脱发呢"→"脱发怎么办，有没有类似固肾功的调理方法？"）
  - Qwen3 系列显式关闭原生思考模式（`enable_thinking: false`），并防御性剥离 `<think>` 标签
- **摘录模式**（未配置 LLM 时）：返回检索原文与出处，系统开箱即用

## 7. 前端设计（React 18 + Ant Design 5 + Framer Motion）

- **视觉主题**：仿 DeepSeek 风格——浅色侧栏（`#F9FAFB`）+ 纯白主区 + 品牌蓝 `#4D6BFE`（选中态 `#EEF1FF`）；Logo 为用户提供的手写体印章图案（自动去背：取样四角背景色做容差透明 + 裁剪），同时用作 favicon 与账户头像（左侧方形印章裁剪版 `logo-seal.png`）
- **整体布局**：左侧导航 + 右侧主内容区的双栏结构
  - **左栏**（固定 264px，垂直满屏，浅灰背景）：顶部 Logo 图、「开启新对话」白色卡片按钮、「书架阅读」入口、会话历史列表（独立滚动，localStorage 持久化，支持删除/切换）、底部用户账户区（印章头像 + 检索模式状态）
  - **主内容区**（自适应剩余宽度，上中下垂直结构）：顶部对话标题栏（固定）；中间独立滚动内容区；底部吸底输入区（大圆角输入卡 + 「深度思考」「智能搜索」胶囊开关 + 蓝色圆形发送按钮，均固定不随内容滚动）
- **消息流**：用户消息为浅蓝气泡（`#EEF1FF`）右对齐；AI 回复为无气泡纯文本（15px/1.78 行高），引用卡片浅底描边、悬停品牌蓝描边
- **滚动与溢出**：`html/body` 禁止滚动，全局仅 `.session-list`、`.main-scroll` 等内部容器可滚；自定义细滚动条样式；滚动定位不依赖 `scrollIntoView`（渲染未稳定时会静默失效），改为直接驱动滚动容器 + 校验重试
- **深度思考**：后端生成更系统的分点分析（摘录模式下返回 5 条而非 3 条）；**智能搜索**：双倍候选 + 每章最多 3 条的多样性约束（引用数 6→8，覆盖更多章节）

## 9. 构建与运行

```bash
# 1. 构建（解析两本 EPUB → 去重 → 分块 → 分词 → PostgreSQL；配置了 EMBEDDING_* 则同时生成向量）
cd backend && python scripts/build_kb.py

# 2. 启动（同时服务 API 与前端）
uvicorn app.main:app --port 8000   # 或 python -m uvicorn ...
# 打开 http://127.0.0.1:8000

cd frontend && npm install && npm run dev   # Vite 代理 /api → 8000
```
